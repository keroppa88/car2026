# 検証プレイ

実際にブラウザでゲームを走らせて、壊れていないかを機械が確かめるための道具です。
改修の前後に走らせて、直したいものが直ったか、他を壊していないかを見ます。

定期実行はしません。必要なときに手で走らせます。

## 準備

一度だけ。

```
cd test
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install
```

ブラウザはこの環境に入っている Chromium を使います。別の場所にある場合は
`CHROMIUM_PATH` で指定してください。

## 走らせる

```
node test/run.mjs                  全部（デモ + 3コース）
node test/run.mjs tokyo            首都高速だけ
node test/run.mjs tokyo sea        指定したものだけ
node test/tokyo.mjs                同じく1本だけ

node test/tokyo.mjs --seconds 120  走行時間を延ばす（既定45秒）
node test/tokyo.mjs --head         画面を出して目で見る
node test/tokyo.mjs --car gtr      別の車で
```

1本でも不合格なら終了コードは1になります。

## 何を見ているか

| ファイル | 対象 | 主に見ているもの |
|---|---|---|
| `demo.mjs` | デモ画面 | コースと曲が進むか、固まらないか、音が1層だけか |
| `tokyo.mjs` | 首都高速 | 縦ループの継ぎ目。CPU車が道路の上に描かれるか、跳ねないか |
| `sea.mjs` | 海岸線 | セグメント接続。継ぎ目で止まらないか、対向車と同方向車が出るか |
| `indy.mjs` | インディアナポリス | 周回とバンク路面。CPU車がバンクを見失わないか |
| `lib/harness.mjs` | 共通 | サーバ起動・ゲーム起動・毎フレームの記録・判定の枠組み |

## 判定の書き分け

出力は2種類あります。**混ぜないでください。**

- `[ OK ]` / `[ NG ]` … **不変条件**。必ず成り立つはずのもの。破れたら不合格。
  例:「CPU車の描画位置は必ず地図コピー間隔の整数倍」「コンソールエラー0」
- `[    ]` … **目安**。環境や運で揺れるもの。参考表示だけで合否には使わない。
  例: 走った距離、CPU車を見た延べ回数、最高速

目安で不合格を出すと、本物でない失敗が増えて誰も結果を見なくなります。

もうひとつ、**「何も起きずに合格」を防ぐ判定**を入れてあります。たとえば
首都高の「ループをまたいだ描画を実際に検査した」は、検査対象そのものが
発生したかを確かめるものです。これが無いと、機能が丸ごと動かなくなった
ときにテストが素通りします。

## 分かっている制約

- **自動運転は遅い**です。首都高で自車が一周するには何分もかかるため、
  `tokyo.mjs` は継ぎ目の手前へ自車を運んでから自然に通過させています。
  運んだ直後のフレームは計測から外しています（`__probeSkip`）。
  そのため「自車のループ通過」は0でも構いません。検査の本命は
  CPU車がルート端で巻き戻るほうです。
- **音の良し悪しは判定できません。** 測れるのは各層の音量が0か0でないかだけです。
  「うるさい」「跳ねて聴こえる」は人が聴いて判断してください。
- **見た目の良し悪しも判定できません。** 座標や数値が壊れていないかだけを見ます。
- **森林地帯は入れていません。** 木が595本・セグメント6区間あり、GPUの無い環境では
  ページが応答を返せないほど重くなって走行を測れません。現状このコースは
  問題なく走れているため、必要になったら追加してください。

## 増やすとき

コース別ファイルには、そのコース固有の判定だけを書きます。共通のもの
（コンソールエラー、路外落下、音の層）は `lib/harness.mjs` に足して、
全コースから使ってください。

判定を足すときは、**根拠の数値を必ず `detail` に出す**こと。
「NG」だけでは、次に見た人（私を含む）が何が起きたか分かりません。
